Panduan Lengkap REST API: Konsep, Implementasi, dan Kode Respons

Ditulis oleh Admin
31 Aug 2026 • 8 min read

Dalam dunia pengembangan perangkat lunak modern, aplikasi jarang berdiri sendiri. Mereka perlu berkomunikasi satu sama lain, bertukar data, dan mengintegrasikan layanan. Di sinilah API (Application Programming Interface) berperan, dan REST (Representational State Transfer) adalah salah satu arsitektur API yang paling populer dan banyak digunakan saat ini.

Artikel ini akan membahas secara tuntas apa itu REST API, bagaimana cara kerjanya, kode respons HTTP yang sering digunakan, hingga contoh implementasi lengkapnya menggunakan Node.js dan Express.

Apa itu REST API?

REST adalah singkatan dari Representational State Transfer. Ini bukanlah sebuah bahasa pemrograman atau framework, melainkan sebuah gaya arsitektur standar untuk merancang aplikasi jaringan. API yang mengikuti prinsip-prinsip arsitektur REST disebut sebagai RESTful API.

Secara sederhana, REST API memungkinkan dua sistem berkomunikasi melalui internet dengan menggunakan protokol HTTP (Hypertext Transfer Protocol). Format pertukaran data yang paling umum digunakan dalam REST API adalah JSON (JavaScript Object Notation) karena sifatnya yang ringan dan mudah dibaca oleh manusia maupun mesin.

Prinsip Utama REST:

  1. Client-Server: Memisahkan antarmuka pengguna (klien) dari penyimpanan data dan logika bisnis (server).
  2. Stateless: Setiap permintaan dari klien ke server harus berisi semua informasi yang dibutuhkan untuk memahami dan memproses permintaan tersebut. Server tidak menyimpan state atau sesi klien.
  3. Cacheable: Respons dari server harus didefinisikan sebagai cacheable atau tidak untuk menghemat bandwidth dan meningkatkan kecepatan.
  4. Uniform Interface: Menggunakan antarmuka yang seragam (biasanya URL dan HTTP method) untuk berinteraksi dengan sumber daya (resource).

Bagaimana Cara Kerja REST API?

REST API bekerja berdasarkan model request-response (permintaan-respons). Klien mengirimkan HTTP request ke endpoint (URL) tertentu di server, dan server merespons dengan data yang diminta atau status operasi.

Klien (misalnya aplikasi web, aplikasi mobile, atau server lain) akan menggunakan HTTP Methods (Kata kerja HTTP) untuk memberi tahu server aksi apa yang ingin dilakukan terhadap suatu sumber daya (resource).

HTTP Methods (Operasi CRUD)

Dalam REST, resource dimanipulasi menggunakan metode HTTP standar, yang sering dipetakan ke dalam operasi CRUD (Create, Read, Update, Delete):

  • GET (Read): Mengambil data atau resource dari server. (Contoh: GET /users untuk mengambil daftar pengguna).
  • POST (Create): Mengirim data baru ke server untuk membuat resource baru. (Contoh: POST /users dengan membawa payload JSON untuk membuat pengguna baru).
  • PUT (Update): Memperbarui resource yang sudah ada secara keseluruhan. (Contoh: PUT /users/1 untuk memperbarui semua data pengguna dengan ID 1).
  • PATCH (Update Sebagian): Memperbarui sebagian data dari sebuah resource.
  • DELETE (Delete): Menghapus resource dari server. (Contoh: DELETE /users/1).

Kode Respons HTTP (HTTP Status Codes) dalam REST API

Ketika server selesai memproses permintaan, server akan mengembalikan balasan beserta HTTP Status Code. Kode ini sangat penting bagi klien untuk mengetahui apakah permintaan berhasil, gagal, atau terjadi error.

Kode respons dibagi menjadi beberapa kategori berdasarkan angka pertamanya:

2xx: Success (Berhasil)

  • 200 OK: Permintaan berhasil. Sering digunakan pada respons GET, PUT, atau DELETE.
  • 201 Created: Permintaan berhasil dan resource baru telah dibuat (Biasanya respons dari POST).
  • 204 No Content: Permintaan berhasil, tetapi tidak ada data yang dikembalikan dalam body respons (Sering digunakan pada DELETE yang sukses).

3xx: Redirection (Pengalihan)

  • 301 Moved Permanently: Resource telah dipindahkan secara permanen ke URL baru.
  • 304 Not Modified: Resource tidak berubah sejak terakhir kali klien memintanya (digunakan untuk caching).

4xx: Client Error (Kesalahan Klien)

  • 400 Bad Request: Permintaan tidak valid, sintaks salah, atau data yang dikirim tidak sesuai (misal: validasi gagal).
  • 401 Unauthorized: Klien belum terautentikasi (belum login atau token tidak valid).
  • 403 Forbidden: Klien terautentikasi, tetapi tidak memiliki izin (otorisasi) untuk mengakses resource tersebut.
  • 404 Not Found: Resource atau endpoint yang diminta tidak ditemukan di server.
  • 405 Method Not Allowed: Metode HTTP yang digunakan tidak diizinkan untuk endpoint tersebut (misal: mengirim POST ke endpoint yang hanya menerima GET).
  • 422 Unprocessable Entity: Format permintaan sudah benar, tetapi server tidak dapat memproses instruksi yang ada di dalamnya (sering digunakan untuk error validasi spesifik).

5xx: Server Error (Kesalahan Server)

  • 500 Internal Server Error: Terjadi kesalahan tidak terduga di sisi server (misal: kode crash, koneksi database gagal).
  • 502 Bad Gateway: Server yang bertindak sebagai gateway atau proxy menerima respons tidak valid dari upstream server.
  • 503 Service Unavailable: Server tidak dapat menangani permintaan saat ini, biasanya karena sedang down atau terlalu banyak beban (overload).

Contoh Implementasi Lengkap (Node.js & Express)

Berikut adalah contoh implementasi REST API sederhana untuk mengelola entitas "Buku" (Books) menggunakan Node.js dan framework Express.

Persiapan

Pertama, pastikan Anda telah menginisialisasi project dan menginstal express.

npm init -y
npm install express

Kode Implementasi (index.js)

const express = require('express');
const app = express();
const PORT = 3000;
// Middleware untuk mem-parsing body berformat JSON
app.use(express.json());
// Simulasi database di dalam memory
let books = [
    { id: 1, title: 'Belajar Node.js', author: 'John Doe' },
    { id: 2, title: 'REST API untuk Pemula', author: 'Jane Doe' }
];
// 1. GET /books - Mengambil semua buku
app.get('/api/books', (req, res) => {
    res.status(200).json({
        success: true,
        message: 'Berhasil mengambil data buku',
        data: books
    });
});
// 2. GET /books/:id - Mengambil buku berdasarkan ID
app.get('/api/books/:id', (req, res) => {
    const bookId = parseInt(req.params.id);
    const book = books.find(b => b.id === bookId);
    if (!book) {
        // Mengembalikan 404 Not Found jika buku tidak ada
        return res.status(404).json({
            success: false,
            message: `Buku dengan ID ${bookId} tidak ditemukan`
        });
    }
    res.status(200).json({
        success: true,
        data: book
    });
});
// 3. POST /books - Menambahkan buku baru
app.post('/api/books', (req, res) => {
    const { title, author } = req.body;
    // Validasi sederhana (Merespons 400 Bad Request jika data tidak lengkap)
    if (!title || !author) {
        return res.status(400).json({
            success: false,
            message: 'Title dan Author wajib diisi'
        });
    }
    const newBook = {
        id: books.length > 0 ? books[books.length - 1].id + 1 : 1, // Auto-increment ID
        title: title,
        author: author
    };
    books.push(newBook);
    // Mengembalikan 201 Created
    res.status(201).json({
        success: true,
        message: 'Buku berhasil ditambahkan',
        data: newBook
    });
});
// 4. PUT /books/:id - Memperbarui data buku
app.put('/api/books/:id', (req, res) => {
    const bookId = parseInt(req.params.id);
    const { title, author } = req.body;
    const bookIndex = books.findIndex(b => b.id === bookId);
    if (bookIndex === -1) {
        return res.status(404).json({
            success: false,
            message: 'Buku tidak ditemukan'
        });
    }
    // Memperbarui data
    books[bookIndex] = {
        id: bookId,
        title: title || books[bookIndex].title,
        author: author || books[bookIndex].author
    };
    res.status(200).json({
        success: true,
        message: 'Buku berhasil diperbarui',
        data: books[bookIndex]
    });
});
// 5. DELETE /books/:id - Menghapus buku
app.delete('/api/books/:id', (req, res) => {
    const bookId = parseInt(req.params.id);
    const bookIndex = books.findIndex(b => b.id === bookId);
    if (bookIndex === -1) {
        return res.status(404).json({
            success: false,
            message: 'Buku tidak ditemukan'
        });
    }
    // Menghapus buku dari array
    books.splice(bookIndex, 1);
    // Mengembalikan 200 OK dengan pesan sukses
    res.status(200).json({
        success: true,
        message: 'Buku berhasil dihapus'
    });
});
// Menjalankan server
app.listen(PORT, () => {
    console.log(`Server berjalan di http://localhost:${PORT}`);
});

Cara Menguji API (menggunakan curl)

GET Semua Buku (200 OK):

curl -X GET http://localhost:3000/api/books

POST Tambah Buku (201 Created):

curl -X POST -H "Content-Type: application/json" -d '{"title":"Clean Code", "author":"Robert C. Martin"}' http://localhost:3000/api/books

Mencoba POST tanpa judul (400 Bad Request):

curl -X POST -H "Content-Type: application/json" -d '{"author":"Penulis X"}' http://localhost:3000/api/books

GET Buku yang tidak ada (404 Not Found):

curl -X GET http://localhost:3000/api/books/99

Kesimpulan

REST API adalah standar industri untuk membangun layanan web yang terukur dan efisien. Dengan memahami prinsip stateless, penggunaan HTTP methods yang tepat (CRUD), dan memberikan HTTP status codes yang sesuai, Anda dapat membangun API yang kuat, mudah dimengerti, dan mudah diintegrasikan oleh aplikasi client (seperti aplikasi mobile, frontend web, atau sistem pihak ketiga).
